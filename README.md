# dsh-talk-track

> 给 [DeepSeek Harness](https://github.com/deepseek-ai) 的商务沟通话术插件：把「客户不回我了」「这周得催款」这类口语交代，变成**结构骨架 + 三版可直接发的稿子 + 对方可能的回应 + 合规体检 + 发前待确认清单**。

```
↓
talk_track → 场景识别 / 结构骨架 / 三版改写 / 异议接法 / 合规检查 / 待确认清单
```

## 它解决什么

写商务话术的难点通常不在文笔，而在三个地方：**结构该怎么排、分寸在哪、发出去会不会出事**。

- **结构**：12 个常见场景各有骨架（称呼 / 开场 / 背景 / 价值 / 请求 / 时间 / 收口），不用每次从零想。
- **分寸**：同一份事实给三版语域——稳健、亲和、推进，让你按关系和阶段挑，而不是靠感觉改。
- **风险**：施压词、绝对化用语、模糊时间、无请求、缺称呼、疑似证件号，发之前先过一遍。

## 和「直接让模型写」有什么不同

| | 直接对话 | 本插件 |
| --- | --- | --- |
| 缺信息 | 容易顺手编一个数字或案例 | 返回 `【待补：…】` 占位，不编造 |
| 语气 | 一次一版，重试成本高 | 三版共用同一份事实，只换语域与顺序 |
| 体检 | 靠模型自觉 | 规则表 + 法条依据，可测、可回归 |
| 稳定性 | 每次结构可能都不一样 | 场景骨架固定，14 项测试守着 |

插件**不内置任何 LLM 调用**。在 DSH 里 agent 本身就是模型，插件再套一层只会多一次幻觉——它只做确定性那部分，判断和收口留给 agent。

## 安装

### 方式 A：挂载本地源码（免安装，改完即测）

DSH 的用户 patch 层支持直接写路径，插件不必装进 profile 的 `node_modules`：

```yaml
# <DSH_HOME>/profiles/<profile>/cordis.patch.yml
- insert:
    - id: talk-track
      name: 'D:\code\dsh-talk-track\lib\index.js'
```

`name` 以盘符 / `/` / `./` / `../` 开头时会被转成 file URL 直接加载。保存后这一层 patch 即时重组；
**改插件源码（`lib/*.js`）需要重启 app** 才会换上新模块，只改 patch 文件不用。

### 方式 B：当作包安装

```powershell
# 需要 pnpm 在 PATH 上
dsh plugin --profile <profile> add github:<owner>/dsh-talk-track
# 或者本地目录
dsh plugin --profile <profile> add D:\code\dsh-talk-track
```

DSH 会把声明了 `dsh.bundle` 的依赖自动登记进 `dsh.profile.bundles`。

**验证**：下一轮对话的工具列表里出现 `talk_track` 即为生效。

### 卸载

删掉 patch 里那条 `- insert: … talk-track …`（方式 A），或 `dsh plugin --profile <profile> remove dsh-talk-track`（方式 B），下一轮对话工具即消失。

## 用法

直接说需求，agent 会调用它：

> 客户看了报价就没回音了，帮我想想怎么跟，别显得在催。

> 这周要催一笔逾期的款，对方是合作两年的老客户，别把关系搞僵。

> 这段话帮我看看有没有问题：张总，我们是最好的供应商，您尽快回复！

### 三种模式

| 模式 | 用途 | 典型说法 |
| --- | --- | --- |
| `build`（默认） | 完整设计：骨架 + 三版 + 对方反应 + 体检 + 待确认 | "帮我写…" |
| `lint` | 只体检一段现成话术，不改写 | "这段话有问题吗？" |
| `variants` | 只要三版改写 | "换个说法，给我几个版本" |

### 参数

| 参数 | 说明 |
| --- | --- |
| `mode` | `build` / `lint` / `variants`，默认 `build` |
| `scene` | 场景名或 id；留空则从 `draft` / `objective` 自动识别 |
| `channel` | `邮件`（带主题行）/ `微信`、`短信`（压到 180 字内）/ `电话` / `面谈` |
| `audience` | 对方是谁：角色、决策权、已知关切、和你方关系。称呼从这里推 |
| `objective` | 这次要拿到的具体结果（别写"推进一下"） |
| `draft` | 原话术或要点；有就基于它改写，没有就出占位版 |
| `value` | 对方能得到的好处，必须是能兑现的事实 |
| `time` | 期望时间点，如 `本周五`、`3 月 31 日前` |

## 输出示例

输入：

```json
{
  "scene": "客户跟进无回复",
  "audience": "某制造企业采购张经理，谨慎，卡预算",
  "objective": "拿到本周五前确认的配置项清单",
  "draft": "张经理您好，之前发您的方案看了吗？麻烦尽快回复一下，我们这边好安排。",
  "value": "新配置能省 15% 耗材",
  "time": "本周五"
}
```

节选（亲和版）：

```text
主题：关于方案的沟通

张经理，您好。
这段时间您那边事情应该不少，我把要说的压成几句，不占您太多时间。
之前发您的方案看了吗？
新配置能省 15% 耗材。
您看是 本周五前方便，还是往后挪到您更顺的时间？
不着急，您方便时回我就好。
```

注意原文那句「麻烦尽快回复一下，我们这边好安排」被删掉了：纯施压、又不带实质信息，
请求改由可兑现的时间点承担（"本周五前"而不是"尽快"）。

工具还会给出对方的四种可能回应及接法、风险与合规检查、发前待确认清单，
以及一句成功标准（这次要拿到什么，怎么算成）。

## 场景库

首次约见 · 客户跟进无回复 · 报价与让步 · 价格异议 · 竞品对比 · 需求澄清 ·
催款账期 · 催交付进度 · 涨价通知 · 续约续费 · 礼貌拒绝与延期 · 投诉安抚
——另有一个 `generic` 兜底骨架，认不出场景时不会硬塞一个场景给你。

每个场景包含：触发条件、默认目标、对方关切角色、可用杠杆、结构骨架、常见异议与接法、常见坑、缺什么信息要先问、成功标准。

## 设计原则

- **三版共用同一份事实**。稳健（事实 + 请求 + 致谢）、亲和（体谅 + 二选一时间 + 不催）、推进（结论先行 + 时间边界 + 兜底方案）——只换语域和顺序，所以不会出现某一版多编了个案例。
- **删掉施压句**。原文里的"麻烦尽快回复一下""我们这边好安排"这类纯催促会被丢掉；压力和理由必须是真的，假的就删。
- **称呼不猜**。只有"姓氏 + 紧邻职衔"成立时才输出称呼，`对方是技术负责人` 不会硬凑出"方总"。
- **场景不抢**。用户明说的场景优先，原文里出现"报价"两个字不会把"客户跟进"抢成报价场景。
- **体检给方向，不替你改词**。绝对化用语（《广告法》第九条）、施压词、模糊时间、无称呼、无 CTA、"你"vs"您"、超长、感叹号过多、疑似身份证/银行卡号。

## 边界

直接拒写、不给替代方案的方向：冒充他人或机构身份、索要验证码或密码、诱导转账到"安全账户"、
退款刷单返利、仿冒官方通知或钓鱼链接、伪造合同凭据与授权、恐吓骚扰式催收。
命中红线时 `build` 与 `lint` 都会返回拒绝说明。

它写的是**沟通方式**，不保证业务结果；数字、案例、承诺必须来自你自己。

## 目录结构

```
lib/engine.js        确定性引擎：场景识别、称呼、体检、三版改写、骨架渲染
lib/scenarios.json   12 个场景的知识（加场景/改结构只动这里）
lib/index.js         DSH 工具注册 + 系统提示片段
cordis.patch.yml     插件包自身的 patch（作为包安装时用）
test/                node:test 用例，14 项
scripts/demo.mjs     打印一次完整 build，肉眼复盘用
```

## 开发

```powershell
node test/engine.test.mjs   # 14 项测试
npm run demo                # 一次完整输出，看排版和语气
```

> 沙箱提示：不要用 `node --test test/`，它会 spawn 带管道的子进程，在受限环境里报 `Error: spawn EPERM`；
> 直接跑测试文件即可（进程内运行器）。

零运行时依赖，`lib/scenarios.json` 是纯数据，改话术不需要碰代码。
